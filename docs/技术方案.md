# RouteGuard v2 · 可核验的骑行路书

> **题目（暂定）**：面向安全攸关场景的可核验生成——以骑行路书为对象的多智能体断言核验方法
>
> **英文**：Verifiable Route Guides for Cyclists: Claim-Level Grounding with Evidence-Gated Multi-Agent Adjudication
>
> **定位**：软件工程（可信 LLM 系统）× 地理信息（空间数据核验），问题来自骑行社区的真实需求。

---

## 1. 从需求出发

先不谈技术。以下是骑友真实遇到的事，按发生频率排序：

| # | 场景 | 发生了什么 | 根因 |
|---|---|---|---|
| 1 | **"全程平路"** | 路书写"休闲平路 80km"，实际累计爬升 900m，骑了 6 小时 | 路书是主观描述，没人核验过坡度 |
| 2 | **补给点没了** | 路书标注的"K42 便利店"三个月前关门 | 静态文本，无时效 |
| 3 | **机非混行** | 没写这段是大车多的国道，骑得心惊 | 关键风险信息缺失 |
| 4 | **撤退无门** | 爆胎后不知道最近修车店、最近能上车的车站 | 保障信息从来不写 |
| 5 | **AI 写的路书更糟** | 让大模型写路书，它编出"沿途风景优美、补给充足、路面平整" | 生成模型会补全空白 |

前四条是老问题，第五条是新问题——而且让前四条更严重。

**一句话概括需求**：
> 骑友要的不是"更多路书"，是**能信的路书**——每句话要么有出处，要么明确告诉你"这条我没核实"。

## 2. 为什么现有工具没解决

| 工具 | 做到了什么 | 缺什么 |
|---|---|---|
| Strava / 行者 / 黑鸟的路书 | 轨迹、海拔剖面、热度 | 文本部分是**用户自由发挥**，无事实约束 |
| OSM | 路面、道路等级、隧道、非机动车道都有 | 骑友**不会用**，也看不懂 tagging 语义 |
| 卫星影像 / 街景 | 能看到真实路况 | 没有工具把"看到的"对齐到"路书说的" |
| 通用 LLM | 能写得像模像样 | **不知道就会编**，且编得比人更自信 |

**空缺**：没有一个工具负责"把路书里的每句话，和可验证的证据对上"。

这件事看起来像信息检索，其实是决策问题：证据往往**不完整、过时、互相矛盾**，
系统必须在"给个说法"和"承认不知道"之间做选择。而这个选择，正是本文的研究对象。

---

## 3. 研究问题

> **RQ**：在证据不完整、有时效差、且多源冲突的条件下，如何让骑行路书的每条事实断言
> 都可追溯到证据，并在证据不足时**显式标注"未核实"**，而不是补全一个流畅但可能错误的答案？

三个子问题，对应三项研究内容：

- **Q1（表征）** 自然语言路书如何拆成**可核验的原子断言**？断言的粒度、类型、极性怎么定义？
- **Q2（裁决）** 同一断言对应多源证据且互相矛盾时，如何判定"支持 / 矛盾 / 未核实"，并保留分歧？
- **Q3（表达与代价）** 把"未核实"作为一等输出后，用户是否更信任、更愿意用？**诚实的代价**有多大？

> Q3 是本文最特别的地方：大多数系统优化"看起来完整"，本文优化"可交付的诚实"，并**量化这种诚实要付多少代价**。

---

## 4. 三项研究内容

### C1 断言级证据绑定（Claim-Level Grounding）

**主张**：路书应被拆成**原子断言**，每条单独核验；段落级引用会掩盖"一段里三句真一句假"。

**断言模型**：

| 字段 | 含义 | 例 |
|---|---|---|
| `claim_id` | 唯一标识 | `C007` |
| `segment_id` | 关联路段（空表示全程断言） | `S003` |
| `kind` | 断言类型（六类，见附录 A） | `slope` |
| `stated` | 路书声称的内容（规范化后） | `"平路"` |
| `polarity` | 正/负断言 | `positive` |

**与 RAG 的区别**：RAG 校验"文档里有没有这段文字"；
本文校验"**这个说法是否被独立证据支持**"，证据来自 OSM / DEM / 街景 / 气象，而不是路书本身。
**路书是待核验对象，绝不能当证据**——这是避免"自我循环"的硬约束。

### C2 冲突感知的核验与分歧保留

**主张**：多源证据冲突时，不应简单取多数或最新，而应**按证据质量与时效加权**，
并把"无法消解的冲突"作为独立状态保留下来，而不是强行给一个结论。

**裁决三态 + 一保留**：

| 状态 | 含义 | 处理 |
|---|---|---|
| `supported` | 证据支持该断言 | 打勾 |
| `contradicted` | 证据与断言矛盾 | 标红 + 给原文证据 |
| `unverified` | 找不到可用证据 | 灰标"未核实" |
| `conflict` | 多源证据互相矛盾且无法判定 | 并列展示两方证据，交用户判断 |

**分歧保留**是刻意的设计：宁可让用户看到"OSM 说铺装路、轨迹显示砂石路"，也不要系统替他猜。

### C3 不确定性作为一等输出（并度量其代价）

**主张**：把"未核实率"作为路书质量的**一级指标**，并研究它和用户信任之间的关系。

**可测的量**：

- **核验覆盖率** = 已核验断言 / 总断言
- **矛盾命中率** = 查出的真错误 / 注入的错误
- **误报率** = 把真话判成矛盾的次数
- **过度保守率** = 标"未核实"但其实有证据可查的比例

**代价假设**：未核实标注太多 → 用户觉得"这工具什么都不知道" → 弃用。
所以存在一个最优点，需要用户实验来定位。**这个最优点的存在性本身，就是可发表的结论。**

## 5. 系统架构

```
┌──────────────────────────────────────────────────────────────┐
│ 应用层   路书报告（逐条断言 + 证据 + 状态） / 修订建议            │
├──────────────────────────────────────────────────────────────┤
│ 核验层   断言抽取 → 证据检索 → 三态裁决 → 分歧保留               │
├──────────────────────────────────────────────────────────────┤
│ 证据层   OSM / DEM / 街景 / 气象 / 轨迹热度（各自带时效与质量）   │
├──────────────────────────────────────────────────────────────┤
│ 路段层   GPX → 分段 → 路段画像（坡度/路况/遮荫/风险）             │
└──────────────────────────────────────────────────────────────┘
```

| 层 | 模块 | 职责 | 状态 |
|---|---|---|---|
| 路段层 | `geo.py` / `shade.py` / `indicators.py` | 轨迹切段、坡度、遮荫、环境指标 | ✅ 已有 |
| 证据层 | `schema.Evidence` | 证据契约（值/源/时效/粒度/质量） | ✅ 已有 |
| 核验层 | `claims.py` / `extractors.py` | 断言抽取、对齐、三态裁决 | ✅ 已实现 |
| 应用层 | `cli.py audit` / `report.py` | 逐条报告 + HTML | ✅ 已实现 |

**为什么要分层**：路段画像是可复用的（同一段路可以被 100 份路书引用）；
断言是每份路书独有的。分层后，核验成本随"路书数"增长，而不是"路书数 × 路段数"。

## 6. 关键方法

### 6.1 断言抽取

**骨架阶段**用规则（正则 + 关键词表），**毕设阶段**换成 LLM 抽取 + 人工校验。

输入示例：
```
- [S002] 坡度平缓，基本是平路
- [S003] 沿途有便利店可以补水
```

输出：

```json
{"claim_id": "C002", "segment_id": "S002", "kind": "slope",
 "stated": "平路", "polarity": "positive", "text": "坡度平缓，基本是平路"}
```

**抽取的难点**（也是论文要写的部分）：
- 一句话里多个断言（"路况好、有树荫、没车"）；
- 隐含否定（"不用担心爬坡"其实是坡度断言）；
- 模糊量词（"缓上"到底是几 %）。

### 6.2 证据对齐

三类对齐，缺一不可：

| 对齐 | 问题 | 处理 |
|---|---|---|
| **空间** | 断言说"全程"，证据是分段 | 全程断言 → 展开到所有段，全部支持才算支持 |
| **时间** | 路书写的 2023 年，证据是 2026 年 | 证据带 `valid_from/to`，过期即降级 |
| **语义** | "平路" vs `mean_slope=2.1%` | 类型化阈值：`平` < 2%，`缓` 2–4%，`陡` 4–8%，`很陡` > 8% |

### 6.3 三态裁决

```python
def adjudicate_claim(claim, segment, evidences, when):
    usable = [e for e in evidences if validate_evidence(e, when)]
    if not usable:
        return UNVERIFIED                      # 没证据就认没证据
    votes = [match(claim, e, segment) for e in usable]
    if any(v == "contradict" for v in votes) and any(v == "support" for v in votes):
        return CONFLICT                        # 分歧保留，不替用户决定
    if any(v == "contradict" for v in votes):
        return CONTRADICTED
    return SUPPORTED
```

**优先级**：`未核实 → 矛盾 → 冲突 → 支持`。宁可说不知道，也不要说错。

### 6.4 报告形态

```markdown
## S003 段（第 1.0–1.5 km）

- ⚠️ **矛盾**「沿途有便利店可以补水」
  证据：OSM shop=convenience 最近一处位于 3.2 km 外（2025-11 更新）
  建议：改为"K3 附近有便利店"，或在出发前确认

- ❔ **未核实**「风景很好」
  证据：无可核验数据源（主观断言不纳入核验范围）
  建议：保留原描述，但标注为"作者主观"

- ✅ **支持**「坡度平缓」
  证据：DEM 计算最大坡度 2.1%（GLO-30，2026-01）
```

## 7. 实验设计

### 7.1 数据

| 数据 | 规模 | 来源 |
|---|---|---|
| 路书 | 20 份 | 骑友授权 / 公开帖子（脱敏） |
| 轨迹 | 20 条 GPX | 同上 |
| 注入错误 | 40 处 | 人工构造（过时 12 / 夸大 12 / 缺失 10 / 矛盾 6） |
| 人工标注断言 | 200 条 | 2 人独立标注，Kappa 检验 |

### 7.2 基线

| 编号 | 方法 |
|---|---|
| B0 | OSM 直接查询（无自然语言对接） |
| B1 | 单 LLM 读路书+资料直接判断（无断言拆分） |
| B2 | 断言拆分 + 简单字符串匹配（无语义/时效） |
| **Ours** | 断言 + 多源证据 + 三态裁决 |

### 7.3 指标

| 实验 | 指标 | 说明 |
|---|---|---|
| E1 抽取 | P / R / F1 | 与人工标注比 |
| E2 核验 | 矛盾召回率、误报率 | 40 处注入错误 |
| E3 冲突 | 裁决准确率、分歧保留正确率 | 构造 40 组冲突证据 |
| E4 用户 | 信任度、决策改变率、SUS | 12–15 名骑友，A/B 对照 |
| E5 消融 | 去掉 C1/C2/C3 的退化幅度 | — |

### 7.4 用户实验设计（Q3 的核心）

**被试**：12–15 名有 1 年以上骑行经验的骑友。

**任务**：给同一份路书，A 组看原版，B 组看核验版，回答：
1. 你觉得这份路书可信吗？（7 级）
2. 你会按它出发吗？（是/否/需补充）
3. 哪一条信息对你决策影响最大？（开放）

**关键假设**：
- H1：核验版信任度显著更高；
- H2：但未核实率 > 40% 时，信任度回落（**过度保守的代价**）；
- H3：矛盾标注比"未核实"更能改变决策。

H2 是本文最有意思的结论：**诚实有最优剂量**。

## 附录 A：六类断言

| kind | 例子 | 主要证据源 | 可核验性 |
|---|---|---|---|
| `slope` | "坡度平缓" | DEM / GPX | 高 |
| `surface` | "全程柏油路" | OSM `surface` / 街景 | 中 |
| `traffic` | "机非混行，大车多" | OSM `highway` / 街景 | 中 |
| `supply` | "沿途有便利店" | OSM POI | 中（易过时） |
| `shade` | "林荫道，晒不到" | 遮荫模型 / 街景 | 中 |
| `passable` | "隧道可通行" | OSM `tunnel`/`access` | 高 |
| `scenery` | "风景绝美" | — | **不可核验，标为主观** |

最后一行很重要：**不是所有断言都该被核验**。把主观描述标成"主观"而不是"未核实"，
是避免"过度保守"的关键设计。
